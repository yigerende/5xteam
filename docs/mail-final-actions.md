# 邮件管理：收尾流程与 OAI 确认

邮件账号行新增「执行收尾」和「OAI 确认」。账号、流程进度、错误、日志及 Help 完整回答都在邮件管理查看，账号不会自动进入 Pro 管理、开通补货或 Team 轮转。

## 使用

- 导入外部账号并补齐 ChatGPT 密码、2FA。经典空间合并已有有效 AT/RT 时可使用原凭据；缺失时复用已有登录授权实现。
- 点击「执行收尾」后异步执行 Pro 管理已启用的最后一步：空间合并、删除账户、API 商户、合并空间2.0。未开启任何一种时提示先设置。
- 第一次执行固定所选方式；修改全局开关不改变已有账号的续跑方式。已完成不重复提交；不明确的提交保留原检查点，避免重复操作。
- 点击「OAI 确认」可独立查询外部账号，支持查看阶段、停止、重试、重新执行及完整回答。单独询问不会把收尾或回款标为完成。
- 操作记录保留在数据库，关闭弹窗不影响任务。账号行显示收尾/OAI 状态，可重新打开查看。任务进行中禁止移组。
- 邮件管理的单个/批量删除是操作员明确删除本地账号的动作，不要求收尾或 OAI 确认完成，也不因开通订单、自动补货、管理分组或运行环境绑定而拦截。账号及当前 Team 轮转投影按原事务删除，历史订单、卡片使用和空间访问账本保留；不表示上游账号、订阅或退款已完成。账号删除后不再进入 OAI 调度，迟到的账号状态更新不能重新创建它。后台自动清理和 Pro 管理继续使用各自原有校验。

## 配置与执行

复用 Pro 管理的流程、母号选择、代理、重试、后续分组、商户及 OAI 设置；同账号互斥、同母号串行与独立 OAI 并发限制均沿用已有工作者。无下游绑定的外部账号跳过 Sub2 分组调整。

收尾完成后的自动 OAI 确认遵守对应开关与等待秒数。显式手动确认立即入队，仍遵守并发和重试设置。停止收尾后可以单独确认，但不会因此恢复已停止的收尾任务。收尾前的旧回答不会作为后来新收尾的确认结果。

## 本地验证

后端 `mail_pro_actions_test.go` 使用隔离数据库与模拟上游，覆盖四种流程、重复点击、模式固定、重启检查点、凭据重导入、匿名拒绝、单独 OAI、停止/重试以及登录互斥。

前端验证使用 `scripts/mail-management-preview.html` 和 `scripts/check-mail-pro-actions-browser.js`。浏览器请求由本地 fixture 接管，核验页面阶段、重复打开不重发、邮件日志弹窗、OAI 回答及记录归属。测试不向真实账号发送邀请、停用、删除或 Help 消息。

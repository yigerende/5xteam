# SIWC 确认授权失败后执行最后一步

Pro 管理 → 推送设置 → Sub2SIWC → SIWC 授权方式下方：**SIWC 授权拒绝后执行最后一步**。默认关闭；本地与 s2 接口共用规则，两种推送模式分别保存配置。

只识别 OpenAI `POST /api/accounts/dynamic-agent-clients/consent/grant` 返回 HTTP 401 且 JSON `error.code=not_authorized`。Python 传递结构化错误码，Go 不通过错误文案猜测。管理接口 401、Token 交换失败、额度查询错误、429 与网络错误均不能直接触发最终动作。

开启时按全自动高级设置的“其他步骤失败重试次数”和“重试间隔（秒）”重新登录授权。例如配置 2 次，是首次失败后额外重试 2 次。每次建立新登录客户端与代理会话，恢复权限只核实原已付款订单，不再创建付款。已用的补货恢复次数计入同一预算；本分支接管后不会再叠加补货恢复次数。

重试耗尽后，当前错误仍为上述精确拒绝、原订单已成功、账号未推送且没有待确认的导入，才执行当前配置的最后一步（合并、合并 2.0、删除或 API 商户）。授权保留失败，推送和额度显示跳过，最后一步记录真实执行结果。没有下游账号时不创建空账号的分组调整任务。

执行前再次核对开关、授权来源、下游连接、订单及停止版本。关闭开关、改变目标、停止任务、已取得凭证或已导入都会阻止新处置。最后一步沿用暂停、并发限制与幂等逻辑；暂停恢复只续最后一步，不重新付款。保存拒绝耗尽记录后、最后一步启动前发生重启，可由原定时器续跑；已经启动的最后一步沿用其原恢复逻辑。

不扫描或回填历史失败记录，不改变普通 OAuth、SIWC 成功流程或下游项目代码。

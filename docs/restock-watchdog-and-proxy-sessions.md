# 自动补货结束与厂商代理会话

## 补货结束

全自动当前最后一步（空间合并、合并2.0、删除账号、API商户）与 Pro 管理页面同口径显示 completed 时，独立后台检查自动结束补货在途，不再等下游分组、OAI或卡台回款。不把未推送的账号记为成功交付，不虚增容量。已有付款/订单/卡/商户和后续收尾继续保存。

活动的持久补货任务连续10分钟没有实质进展则强制结束。独立检查每5秒运行，只读取活动任务，每轮最多100项，不访问供应商，不等待监控采样；正常负载下到期后最多约5秒处理。首次进入阶段、首次完成阶段才推进计时；轮询、心跳、重复报错、同一步重试不会续期。计时保存在SQLite，重启保留。历史任务首次采用已保存阶段时间，不用UpdatedAt。

超时持久化停止版本并取消对应准备/全自动/合并工作者；不同任务和后来的手动操作不受旧结果影响。已经成功推送、正常等待额度的账号只结束补货核验占位，后续额度流程不被终止。终态任务和已经完成交付的任务不再检查。限额/预算/失败熔断配置保持，未知付款与开卡保留原财务状态和占用，不能因此重付原订单。手动独立流程未领取补货任务的，不由此补货看门狗接管。

## 厂商会话

代理管理增加皇冠（IPRoyal）、CLI（Cliproxy）、1024、711、自定义选项，默认PH菲律宾、60分钟。原地址/静态保持旧地址兼容。厂商规则参考星桥订阅手动代理：皇冠参数放密码country/session/lifetime；CLI/1024放用户名region/sid/t；711放用户名region/session/sessTime，保留sessAuto；自定义支持{country}/{session}/{minutes}。

每个新的登录客户端领取独立会话，单个lease生成一次并缓存；首次登录→付款RPC→后续OAuth沿用同一地址。额度重新登录也是新客户端，使用相同厂商配置。网络故障冷却以原代理资源为单位，下一次重登立即选择原配置备用，生成备用厂商的新会话；已开始的会话不因后台编辑/恢复主用而换线。已提交付款不重放。冷却恢复检测、手动连接和质量检测也使用对应厂商参数。

60分钟是提交给厂商的粘性有效期；厂商实际出口和地区必须运行验证，不由Space伪造或保证。不同账号使用独立随机会话，出口IP仍由代理供应商分配。同会话需要超过有效期时沿用原协议规则，不在业务请求中途暗自换IP。

新增proxy_sessions、pro_restock_progress及结束清理触发器，原代理URL及主备/冷却配置不改。上线后仅按用户指定为merge三个既有资源设置iproyal/711proxy/1024proxy、PH、60；其他代理和Space user原配置保持。旧API仅编辑名称地址不会丢失新增参数。

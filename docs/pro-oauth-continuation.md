# Pro 第三步授权续验证与重试

## 正常续验证

SIWC 选择已有账号后保留完整返回状态。只在要求密码时提交密码，只在要求 MFA 时用该响应的 TOTP 因子验证；既支持只补密码、直接 MFA，也支持密码后 MFA。直接返回确认授权或回调时沿该结果继续。验证通过但没有下一跳、或回到网页版时，只重访一次原授权链接，不更换 state、PKCE、nonce、客户端、Cookie 或代理。

第一步登录的“密码只提交一次”保护保持不变。第三步使用独立验证边界，一轮授权的同一挑战只提交一次，避免重复密码/MFA 循环。原 upstream.py 不改动。已有授权 HAR 仅包含正常选择账号→确认授权路径，追加验证使用现有共享密码/MFA 协议，新增分支用隔离 HTTP fixtures 验证，并不声称已对真实账号复现所有分支。

## 所有第三步失败使用后台重试配置

- 普通 Codex、SIWC 本地、SIWC s2 都读取 Pro 的 retry_count、retry_interval_seconds。2 次代表首次执行之外再试两次，0 次不自动重试。
- 登录会话仍可用时，仅重做第三步；明确会话失效、回到登录入口，或执行子进程已退出时，走已付款恢复登录。恢复登录后必须核对原成功订单、邮箱和空间，付款 RPC 仅核实原订单。
- 已取得的新凭据在内存中保留，保存失败先重试保存。s2 回调结果不明时先复用原待确认记录与幂等键核实导入，不能直接新建第二个账号。
- OAuthRecovery 在账号状态中持久化订单、来源、下游、次数、等待时间。重启不清零；普通付款重试计数不增加，开通时间/推送起算时间不改变。补货兜底不能另加一组次数。
- 用户停止会取消等待和子进程，恢复次数仍保留。服务重启沿用现有安全恢复策略：未完成登录会话标记 interrupted，需要手动继续；不会自动重付。主动继续仍保留已用自动次数与未到期等待时间。
- 耗尽后失败并释放工作者、卡预留；确认没有下游待核实导入时也释放补货执行占位，原已付款订单保留等待人工处理。下游导入结果不明仍保留核实状态，防止重复补入。密码/MFA/普通授权失败不触发最后一步。既有明确开启的“确认授权 401 / not_authorized 重试后收尾”仍只对精确错误生效，并共用已用次数。

## 验证范围

Python HTTP fixtures 覆盖两种 SIWC 来源的密码、MFA、直出回调、无下一跳后重访、正常无挑战路径，以及同一客户端/代理/Cookie/state/PKCE 保持。第三步边界覆盖普通报错重试、已保存凭据复用、s2 未知导入核实、会话失效退出到已付款恢复、停止与次数耗尽。

Go 隔离付款端覆盖三种授权来源、同会话重试/重新登录/子进程退出/次数耗尽，确认原订单唯一、付款一次、时钟不变、间隔生效、停止立即取消、补货不追加重试。Store 测试覆盖多账号并发领取、同账号 24 路竞争、重启后的剩余预算和状态守卫；不对真实账户制造付款或退款。

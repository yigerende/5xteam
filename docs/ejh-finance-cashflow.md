# EJH 成本统计与本金回收

成本页分开显示消费收益、实际成本、退款本金回收和净利润。净利润 = 消费收益 − 实际成本，退款本金不是营业收入。

退款入账日期保留用于资金回收统计；退款以卡片、授权号和币种匹配原清算，抵减原清算日期成本。多笔清算按原发生顺序分配，部分/多次退款去重且不超过对应原支出；无法明确归属的差额保留待核对，不计入到账日利润。原期间成本、利润随已核实退款更新。例如原支出 100 USD、后来退回 95 USD，原期间保留 5 USD 本金成本；到账日单独显示回收 95 USD，当天利润不因此增加。实际手续费继续计成本，销卡转主余额不重复形成利润。

“全部”累计口径仍是消费收益减净成本，本金不是额外收入。只付款本金的排除沿用同一原日期，避免跨天重分类产生假费用。

当前 MASTER_B1_5 的成功清算退款在销卡前不恢复可用卡余额，按成功退款流水的 USD refundBuyPrice 单列“退款待销卡结算”。卡片已销卡后移出该项，由最新主余额体现。缺少金额时显示待核实，其他卡产品不推断同样规则。此项只补充资金资产核对，不修改原始余额、订单或交易记录。

旧下游消费异常只影响其起止日期覆盖的周期，历史累计金额保留。活动账号尚未按日核对完成、缺失金额或无明确日期的数据继续提示不完整，不伪造最终利润；全部统计仍使用原累计消费口径。

性能：成本页使用受管理员认证保护的 `GET /api/ejh/finance/report?mode=day|week|month|all&date=YYYY-MM-DD`。服务端在一个只读 WAL 快照中收集财务证据，复用前端现有十进制公式生成当前周期结果；完整历史证据只在服务器内部用于跨天退款关联。首页不再传输卡片/流水全量，`section=events|accounts` 按需分页，支持 `page/page_size/query/kind/day`；账号明细仅展开后请求。明细带汇总的 revision，避免刷新期间混用两批数据，快照已淘汰时返回409并刷新汇总。

同一应用最多一个财务计算进程，并发读取复用结果，取消页面不阻塞其他请求；计算限时25秒，Node内存上限256MB。最多缓存8个周期/版本，财务数据变动（含每日消费增删改）自动使新汇总失效。计算使用容器已有Node 20+，没有新增上游请求。`npm run build` 同时生成并嵌入 `internal/financecalc/report.mjs`，后续调整公式必须重新构建；旧finance和overview接口保留给原调用方。

浏览器只在内存保留最近结果，重进页面先显示再更新；最多24份、5分钟，认证状态变化时清空，不写入本地存储。日期切换取消旧请求，搜索合并短时间连续输入，离开页面停止定时刷新。读取失败保留同周期上次结果并提示，不能把其他日期结果显示为当前日期。

验证覆盖跨天/重复/部分退款、销卡前后资产转移、缺失金额、旧期间异常隔离、累计与分期口径、Worker 计算复用，以及紧凑接口不读取损坏旧快照。真实规模数据经过桌面及手机页面验证，不调用上游付款、退款、销卡操作。

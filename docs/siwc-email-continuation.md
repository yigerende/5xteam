# SIWC 授权邮箱续验证

- 邮件管理支持 `邮箱----ChatGPT密码----2FA密钥----接码链接`，三横线、Tab、逗号也可作为分隔符。第四字段为 HTTP(S) 链接时，保存为接码链接；原 TOTP + AT、Outlook OAuth、链接 + Session JSON 格式保持兼容。
- Pro 第三步两种 SIWC 授权方式均支持直接邮箱验证、密码后邮箱验证、密码 + 2FA 后邮箱验证。继续使用当前客户端、Cookie、设备标识、代理和原授权参数。
- 上游返回 `email_otp_send` 时沿返回地址发码；已到 `email-verification` 时直接取码，不额外重发。复用现有接码适配器及纯文本、JSON、HTML 解析。显式发码前采集旧码；已发码的页面不重新采集以免排除新码。
- 沿用接码轮询节奏：先等 16 秒，最多查 3 次、间隔 30 秒。也保留现有“未发现新码时尝试最近已见验证码”的兼容逻辑，上游最终校验有效性。缺少链接、超时、验证码无效均明确失败；重复身份验证/发码有边界。
- 验证后按响应继续密码、2FA、consent、回调或重访原授权链接。只有成功回调才进行凭证交换/推送。
- 内部取码轮询不消耗第三步重试次数；整次授权失败交现有持久化重试预算与间隔处理。手动停止仍终止子进程，不增加付款、重置开通起算或自动收尾。

验证：`frontend/scripts/check-mail-import.mjs`、`internal/test_protocol_siwc_email.py`、原协议回归、Mail 导入/凭据保存测试，以及 Pro 授权重试/停止/耗尽释放补货占位测试。协议使用隔离 HTTP 场景，不对真实账号重复付款或申请收尾。

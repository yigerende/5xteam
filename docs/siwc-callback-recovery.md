# SIWC s2接口回调409恢复

全自动第三步收到 `409 / SIWC_CALLBACK_UNCONFIRMED` 时，只有下游同时返回 `metadata.failure_stage=exchange`、`metadata.reauthorize_allowed=true` 才自动恢复。这表示换凭证或校验已经失败退出，尚未调用创建账号。普通409、正在处理、幂等冲突、缺少该证据的旧响应和创建结果不明均保留原请求。

Space 在同一事务核对原成功付款单、流程与停止版本、待确认请求未变化和代理未绑定，记录一次恢复机会、删除该账号旧请求及未使用的代理预占。普通重试次数、卡、付款单、补货任务不变。不扫描历史账号。

仍在执行中的第三步复用当前客户端、Cookie 和代理会话，新建授权链接并重新取得code，使用新幂等键导入。旧会话已结束时，手动重试先核对原pending结果，再走已付款重新登录恢复。每次执行最多自动恢复一次，失败后停止；用户明确点击原账号重试可以开始新的恢复执行。普通后台调度及重启不重置机会。

已成功导入但回复丢失继续原幂等请求恢复账号与凭据，不重新创建。无法确认的导入保留请求，由现有手动关联入口处理。恢复过程的下游接口、原付款和补货占用均沿用现有规则。

SIWC日志仅记录exchange/create_account阶段及timeout/network_error/id_token_validation等受控分类，不写回调、Token或代理凭据。升级顺序先SIWC再Space；旧SIWC没有恢复标记时Space保持原核对行为。

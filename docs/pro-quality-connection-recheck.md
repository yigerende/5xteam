# Pro 连续检测失败的连接复核

“连续检测失败次数”达到配置阈值后，Space 在执行降智处理前请求当前绑定 Sub2 的 `POST /api/v1/admin/accounts/{id}/test`。沿用 Sub2 的认证、账号代理和普通测试方式，模型 `gpt-6.1-sol`、提示词 `hi`、`mode=default`、`endpoint=original`，超时 45 秒。

- 仅 SSE 返回完整成功事件且有回答时恢复“正常”，清零连续失败，取消尚未开始的降智处理。
- “复核降智状态码”默认 `429,502,503`，支持用英文逗号填写 400～599 状态码；留空或旧配置缺少字段时使用默认值。保存时去重、去除空格，非法输入拒绝保存。
- 仅 SSE 错误事件明确返回的上游状态码命中配置时，才按降智策略处理。默认 400 模型不支持、401、403、500、504 均不触发；200 成功仍恢复正常。
- 网络超时、Sub2 管理接口本身的 HTTP 错误（包括外层 503）、空回答、不完整响应、缺少上游状态码均只记录“复核未确认降智”，不暂停调度、不切组、不合并、不转 SIWC；保留失败计数，下次按原查询间隔复核，不把未确认误标为恢复正常。
- 整个任务取消或账号绑定、处理配置发生变化时，停止本次处理。测试期间手动停止账号也会阻止后续动作。
- 复核适用于失败次数触发的切组、SIWC 转入，以及全自动最后一步的合并、合并 2.0、删除、API 商户。已经明确确认的答题或模型降智不因普通连接成功而覆盖。
- 全自动最后一步排队后，在真正开始前重新检查；此时若连接恢复或状态码未命中，取消排队处理且不消耗合并重试次数。已经开始的业务步骤按原续跑规则处理。明确账号停用仍沿用死号处理，和降智状态码配置独立。
- 同一条上游失败样本在复核成功后不会重复累计，也不会因轮询不断延长成功结果有效期。新的失败样本重新计数；结果有效期仍用原配置。

最近复核时间、上游状态码和结果保存于账号状态，在“智商情况 → 检测详情”展示；检测日志同时记录复核结果及当时的状态码配置，不保存完整测试回答。配置/API 字段为 `connection_failure_http_statuses`，保存在原 `pro_quality_settings`，不需数据库迁移，不改变启用开关。

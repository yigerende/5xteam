# Pro API 商户

在 **Pro 全自动配置 → 空间合并/删除账户/API 商户/合并空间2.0** 填写 **API 商户地址** 和 **API 商户密钥**，开启 **查额度达标后 API 商户** 并保存。自动合并、自动删除、API 商户和合并空间2.0 四个开关互斥；全部关闭时保留原全自动合并行为。

商户地址必须填写完整提交接口，支持 HTTP/HTTPS、端口和任意接口路径，例如 `http://127.0.0.1:18740/open/v1/requests` 或 `http://127.0.0.1:18740/v1/cemifh`。提交直接请求填写地址，不自动追加或替换路径；留空使用原接口 `https://refunds.llmrefund.com/v1/refunds`。密钥留空保留已保存值。自建商户需兼容相同的提交和进度查询协议；支持原商户申请编号响应及独立退款工作台的 `ids` / `refund` 响应封装。

选中 API 商户后，额度达标、推送超时、降智的“按配置执行”及每日 EJH 定点处理使用商户流程。无需目标母号，不调用本地 OpenAI 合并或删除流程。全自动阶段最后一步显示“API 商户”，旁边显示独立商户状态列；列表的“API 商户”筛选仅包含商户最终成功的账号。处理中、失败和中断的账号留在流程中。

## 接口与状态

1. `POST {商户地址}`，Bearer API Key；请求头包含持久化的 `Idempotency-Key`。请求体为 `authorized:true` 和一个账号的 `email`、ChatGPT `password`、`totp_secret`。不需要本地重新登录或获取 AT。
2. 受理后保存申请编号，每 15 秒调用 `GET {商户地址}/{id}`。如果提交仅返回批次编号，先通过文档提供的批次过滤查询定位本账号的申请，再按申请编号查询。
3. 核对响应的申请编号和邮箱，仅 `status:succeeded` 且账号未被报告封禁时完成。`queued`、`processing`、`verifying`、`attention` 继续等待；`failed`、`cancelled`、`banned` 停止后台查询并显示结果。HTTP 202 不代表最终成功。成功后不再定时查询。

状态列显示提交申请、查询进度、处理完成，以及申请编号、受理时间、最近查询、下次查询和成功时间。三点菜单及状态列可以手动续跑；已有申请只查询原申请，不重新创建。未知响应不能标记成功，也不展示上游可能含凭据的原始响应。

已明确失败或取消的申请另有“重试（重新发单）”按钮，实时核实原单失败后生成新申请，保留原单日志。规则见 [手动重新发单](pro-merchant-retry.md)。

## 恢复和停止

- 商户地址、密钥、原提交载荷一起加密保存。请求在发送前就保存幂等键及原始载荷；网络中断或重启不会更换幂等键。修改账号密码、2FA、商户地址或密钥不会改变原申请的地址、重试载荷及查询凭据。升级前没有地址快照的历史申请固定使用原商户，不能被新配置转移。
- 未取得申请编号的提交异常最多自动尝试 3 次，之后保留原申请等待手动续跑。进度查询暂时失败则按 15 秒间隔继续查询。
- 改为合并/删除模式不会改变已在途商户申请的处理方式。已有商户申请的账号不会重新开通、重新推送或再次触发额度、超时和降智收尾。
- “停止全自动”同时停止本账号商户请求与查询计时；已被商户受理的申请无法撤回。手动续跑恢复原申请。最终成功后不再自动查询；未完成的下游清理可单独手动续跑。
- 受理后遵循原下游退出及所选移出后分组配置，卡台只记录申请待回款。商户成功不会伪造卡片退款流水、退款金额或到账，资金统计仍以原卡台数据为准。

接口参考：https://refunds.llmrefund.com/api-docs 。公开 OpenAPI 未声明响应结构，因此对申请身份、最终状态执行严格校验；无法识别的响应保留待处理信息。

## API 收费

自动 API 商户开关下可填写“每次成功收费（USD）”，默认 0。金额在首次提交时固定，商户最终成功后只记一次。两个卡台的账号回款、卡片成本和财务总账显示 API 收费；处理中和失败不收费。该费用属于外部业务成本，不扣减卡台余额、不冒充卡台流水、不改变原资金核对差额。

## 卡片平台与 EJH 正常待定

两卡台开卡模板可选择 OAI / CC；旧模板和旧卡按 OAI 兼容。开卡记录保存当时的平台和模板名称，修改模板不改变已有卡的平台。卡片管理默认显示 OAI，可切换 CC；卡片和列表均显示模板名称及平台。

Pro 银行卡、全自动选卡、自动补货和模板选择只使用 OAI。CC 可在卡台手动选择对应模板开卡，环球自动提现、自动回收及开卡前自动腾位不会操作 CC；手动操作仍可用。

EJH 卡片管理增加“正常待定”。卡片操作可“移到正常待定”或“恢复正常”；待定卡不参与普通同步或页面自动刷新，但保留原卡片状态与 Pro 使用规则。在正常待定中点击“一键刷新正常待定卡片数据”，仅刷新当前 OAI / CC 分类中的待定卡资料、余额和完整交易明细。已销卡不能移入待定。

验证使用模拟商户与虚拟卡片，没有为测试向商户提交真实账号或发起真实资金操作。

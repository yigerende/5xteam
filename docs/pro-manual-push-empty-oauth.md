# Pro 手动重新推送与 OAuth 空组判断

## 手动推送

2026-11-11：Pro 管理的单个、批量手动 Sub2 推送，在本次请求前读取最新保存的连接、分组、模型、代理、优先级与并发配置。已推送账号不再因旧下游绑定而被发往旧地址。自动查询额度、费用和原有收尾仍使用账号实际成功绑定的连接。

新推送先保存独立的加密目标引用 `pro_pending_push_target_id`，成功取得下游账号并提交本地记录后，才切换正式绑定和后续查询来源。切换清除旧站额度/费用缓存，避免两站数字账号 ID 相同造成串用；已留存的财务历史保持。不会自动删除旧下游账号。

明确拒绝且没有待确认创建记录时，可在下次手动推送采用最新设置。超时、5xx 或响应不明时保留新推送的原目标、完整加密请求、代理和幂等键，重试先核对这一请求，不因修改设置跨站再建。重启或保存账号凭据不丢失待确认目标。新推送失败时保留旧有效绑定及其监控状态。

重新推送不改变首次推送时间、累计时长、原超时开关和分钟数、超时截止时间，也不清除已有结束时间。首次从未成功推送的账号仍按原规则开始计时。VM2 槽位和托管 SIWC 转入保持原生命周期；本次手动切换仅针对普通 Sub2（包括直接 SIWC）推送。

## 空分组

自动补货的空组启动、兜底的源组空判断，共同读取 Sub2 对应监控分组中的 OpenAI OAuth 账号数量：

- 只统计 `platform=openai`、`type=oauth`，API Key 不计入。
- 停用、不可调度、无本地 Pro 记录的 OAuth 账号仍是成员，计入数量。
- 按配置监控组统计，不混入附加采购组、SIWC 目标组或其他站点账号。
- 分页缺失、请求失败、账号类型/平台不明确时，不按空组触发。兜底保留原状态并显示错误；补货仅暂停空组触发，其他已验证供需规则沿用原逻辑。
- 使用既有完整账号采样结果，不新增每账号请求。空组补货仍扣除同组在途，遵守预算、冷却、并发和快照时效。

快照保存 `monitor_oauth_count` 或 `monitor_oauth_error`，决策记录显示当时的数据；旧记录标明没有记录 OAuth 数量，不用当前数据重算历史。

## 验证

隔离测试覆盖真实单个/批量 HTTP 入口、跨地址相同账号 ID、新分组/代理/并发设置、首次及结束时间保持、未知响应后重启和凭据保存、明确拒绝后的切换、旧站迟到费用响应，以及 API Key/停用 OAuth/外部 OAuth/不完整类型在补货和兜底中的行为。前端类型、决策解释、补货/兜底组件与生产构建一起验证。测试不向真实客户账号发送推送或付费请求。

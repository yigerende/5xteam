# EJH 卡台读取与刷新

销卡分为“处理中”和“已销卡”，进入销卡默认查看处理中（含结果待确认）；点击分类按需读取对应分页，已销卡仍按成功时间倒序。后台同步、自动销卡和原申请结果查询保持原逻辑。

卡台按当前分区、筛选和分页读取 `/api/ejh/view`，审计按需读取。保留当前卡的账号、流水及跨卡手续费分摊依赖。总览通过 `/api/ejh/overview` 读取完整历史，在 Worker 使用原有公式计算后供统计组件共用，不按当前页截断财务范围。

进入页面只读取已保存数据。页面可见时按保存的 `page_refresh_seconds` 检查版本；有变化才重新读取当前列表和总览，未变化时仅重算时间相关展示。未完成操作按 ID 查询进度，不重发申请。关闭页面取消读取和后续页面查询，后台业务继续。

显示快照用独立只读 SQLite 连接。同一版本并发读取共用计算，取消的请求不会排队重算。版本由固定连接的 `PRAGMA data_version` 提供；保留计算开始前的版本，期间发生写入则下次读取失效。缓存只供展示，付款、选卡、占用和销卡校验仍使用原持久化记录及互斥。

完整总览独立在后台加载，最多等待45秒，适应历史数据经公网传输的时间；不阻塞列表和操作。

按钮收到结果立即提示，后台更新列表和总览；读取失败与操作结果分开展示。手动同步、失败项重试、后台对账和销卡后未回款的必要查询保留原业务范围。

公共请求层对 GET 默认设置 30 秒上限，显式超时优先。传输断连最多重试一次，共用原截止时间和取消信号；HTTP 业务错误及 POST/PUT/DELETE 不自动重发。

邮件分页、Pro 设置和补货记录使用独立读快照；显式有效分页尺寸不再读取主连接设置。导入在原保存锁内返回新增/更新结果，避免每个账号扫描全表，成功后不等待列表刷新；归属和历史身份保持原样。

验证覆盖分页、依赖、排序、缓存并发/取消/失效、独立读取、并发导入计数；前端断连/超时/切页/操作结果与读取隔离，以及原财务、退款、只付款、死号和卡状态回归。没有通过真实付款或销卡做测试。

# API 商户手动重新发单

API 商户状态列及全自动进度窗口新增“重试（重新发单）”。只在已有明确申请编号、商户最终返回 failed/cancelled 且未成功时显示。原“查询 / 续跑进度”仍查询原申请；提交响应不明时仍使用原幂等键，不能当成失败另发一单。

点击调用 `POST /api/pro-accounts/{email}/merchant-retry`，请求体为当前显示的 `request_id`。后端持有该账号操作锁，先用原加密快照查询商户原单，再确认 failed/cancelled。查询超时、身份不匹配、处理中、核实中、待跟进、成功、封禁均不新发。此查询不持全局业务锁，不扫描其他账号。

确认失败后，在同一事务中归档旧商户状态到账号流程日志、生成新的幂等键、更新本轮商户状态。原供应商、接口、密钥及申请资料快照、服务成本和卡片绑定保持；已完成的下游退出保持。订阅付款、授权、推送、回款记录不重置。新单被受理后沿用每 15 秒查询和原成功收费逻辑。

页面忙碌状态、账号操作锁、原请求编号匹配及费用记录共同防重复：连续点击、多个页面及丢失响应后重试不会产生多个新申请。核实过程中用户停止流程时，停止版本变化会阻止本次重新提交。重启后按已保存的新幂等键继续，不再生成另一笔新单。日志只归档商户进度及新旧编号，不写密码、2FA、Session 或商户密钥。

验证使用隔离临时库及模拟商户，覆盖 24 并发事务、8 并发按钮请求、原单实时状态、请求丢失、旧页面重放、停止竞争、成功收费保护、凭据不变、旧单日志与组件渲染。正式真实订单只按用户明确指定重新提交一次，不作为测试流量。

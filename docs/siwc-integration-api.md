# SIWC 标记与可选 s2接口授权

Space Pro → 推送设置 → Sub2SIWC 增加 `siwc_authorization_source`：空值 / `local` 保留本地授权，`sub2api` 使用目标站接口。不会自动改现有配置。第三步按执行快照显示「SIWC 授权（本地）」或「SIWC 授权（s2接口）」，普通 OAuth 保持 RT/AT；第四步推送仍独立显示。

本地创建、原账号重新推送、邮件 SIWC 导出都带 `extra.auth_provider=siwc`、`import_source=siwc`、`codex_fingerprint_mode=off`。插件只看 metadata 中的 extra，不读 credentials.auth_mode；缺标记会走普通 Codex 路径。原账号重新推送复用原 ID 并校验返回标记，不覆盖分组和额外配置。

## 接口方式

1. 由所选目标站生成 URL；PKCE verifier/state/nonce 留在目标站。
2. Space 沿用当前登录客户端、Cookie 和代理完成授权，不重复密码/2FA。不修改登录引擎/挑战处理。
3. 用回调、邮箱、分组、并发、模型和选定绑定代理调用目标站回调接口，目标站换 token、验签/身份/授权范围，直接导入分组。
4. 返回账号 ID、已验证 RT/AT。Space 加密保存 SIWC 与独立网页 AT，完成 oauth 和 push 两格，继续原额度及后续流程。

授权交换使用生成时提交的瞬时登录代理，只在目标 OAuth 会话内保存，不写入代理池；账号之后使用 Space 原代理选择规则，累计绑定计数、最大次数和定时解绑保持原实现。

## 重试及边界

导入前用原推送机制加密保存完整请求、连接、分组、代理、幂等键；响应丢失先重试原回调，不另行建号，不重付。目标站 30 分钟 OAuth 会话内串行消费一次授权码；完成导入的幂等结果持久保存账号 ID（不保存 token 响应），重复请求读取原账号凭据。24 小时后禁止自动重放旧导入。

目标进程在授权交换与建号期间重启，或数据库创建结果不明，保持待确认并报明确错误，不盲目建第二个账号。尚未消费的 OAuth 会话重启后需重新授权。续期策略、付款、普通 OAuth 与原降智托管转入流程不改。此次不批量重写历史已推送账号。

## 验证

离线测试覆盖：SIWC 标记/普通 OAuth 隔离、同会话接口授权、回调重复参数/错 state/错用户、并发仅交换与建号一次、代理固定、响应丢失后沿用原请求恢复、配置保存与模式切换、第三和第四步骤保留。无真实付款或推理压测。

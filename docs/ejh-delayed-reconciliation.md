# EJH 延迟入账的付款、回款关联

部分 EJH 流水的 `tradeTime` 为无时区 UTC，`createdAt` 为北京时间。原有独立时间校正只接受录入延迟不超过 30 分钟的记录。卡商批量延迟录入数小时后，同卡真实付款落不到开通时间窗口，付款显示待识别，撤销回款也无法关联，自动销卡因缺少付款证据跳过。

对账时增加订单佐证：成功 EJH 订单、同卡、OpenAI/ChatGPT 商户、无显式时区的成功授权流水；原时间不能匹配任何成功订单，校正 8 小时后必须只匹配一个订单的既有付款窗口，且不能晚于卡商录入时间。其他情况保留原有判断。按卡索引候选订单，不增加上游请求。

延迟撤销沿用同卡、同授权码、同卡商订单、同币种和商户校验，以已核实授权时间纠正不可能的“撤销早于付款”。既有同卡 FIFO 回款顺序、手动关联、重复去重规则保持。后续清算仍合并为同一授权事件。

只调整对账使用的时间，不改卡商原始字段、金额、手续费或成本入账日期，不根据余额单独确认回款。启动及后台同步的既有对账会修复历史漏关联。只有付款而无撤销/退款的账号仍等待回款；销卡仍需原有完整资金证据检查。

回归覆盖：延迟付款和撤销、后续清算去重、缺失/歧义证据、显式时区、早于录入约束、仅付款无回款、重复对账、流水先后到达、重启持久化、卡片占用释放及自动销卡资金证据。

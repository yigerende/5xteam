# 手动关联已有 Sub 账号

Pro 管理的推送列提供“关联已有 Sub 账号”。用于账号已经在当前 Sub 手动授权导入、Space 的自动授权或推送未完成的情况。支持普通 OAuth 和两种 SIWC 授权方式。

## 操作与匹配

`POST /api/pro-accounts/{email}/link-sub`（管理员认证、空请求体）。按当前推送设置的站点、授权类型及全部所选分组查找账号，以凭证中的邮箱精确匹配；账号名称不作为身份依据。分页读取后再次读取目标账号，只有唯一有效候选才关联。找不到、重复、账号身份或配置改变时返回明确错误，不创建远端账号。

成功返回 HTTP 202 和更新后的账号资料。页面更新当前行，后续进度使用原本页轮询。相同账号正在运行时返回忙碌错误，重复点击不会并发提交。

## 状态与后续

- 已付款的全自动流程保留原订单，从额度步骤继续；不执行付款、SIWC 授权或账号创建。被手动停止或超时保护停止的失败流程可以显式关联恢复。
- 关联记录固定远端站点和账号 ID。已有推送计时起点保持；首次关联且从未推送的账号，从关联成功开始计时。
- SIWC 的 RT/AT 继续由远端持有，不复制或伪造 Space 本地 OAuth 凭证。Space 单独加密保存关联及额度网页 AT；界面显示“已在 Sub 授权”。
- 额度阶段重新登录取得网页 AT，按原付款订单固定空间 ID，核验邮箱、空间及有效期后，只更新原远端账号的网页额度凭证，然后调用原 SIWC 额度刷新接口。
- 额度失败保留关联，按既有周期重试；达到原配置阈值后继续既有收尾。已进入收尾或已完成的流程不会借此重开。
- 保留账号互斥、乐观版本检查和跨账号重复绑定检查；匹配期间发生停止或其他修改时不覆盖新状态。

## 授权校验修复

本地和 s2 接口方式共用 Space 的 SIWC 取 code 实现。选择账号、读取授权会话、确认授权三个请求分别生成新的 `authorize_continue` Sentinel；保持原登录客户端、Cookie、设备和代理会话。生成失败不发送带旧令牌的请求。s2 方式仍由 Sub2API 生成授权链接及完成回调换取 RT/AT、导入分组。

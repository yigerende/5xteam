# 查额度达标后 API 商户：星桥代退

开通设置的“空间合并/删除账户/API 商户/合并2.0”中新增 API 商户供应商选择：原 API 商户、星桥 StarBridge。默认仍为原商户，不覆盖正式地址、密钥、业务开关或费用设置。手动 API 商户与全自动达到额度/超时后的商户步骤共用适配。

星桥默认提交地址 `https://bridge.ccgpai.com/api/v1/refund/orders`，可填写完整自定义地址。填写星桥账户 API Key，需星桥已开启代退受理且钱包余额足够。两个供应商的地址、加密密钥分别保存；留空密钥保留该供应商原值，切换不串用密钥。新增独立密钥表为空，不复制其他系统凭据。

## 接口契约

依据 StarBridge `de20862` 的 `backend/openapi.json`（2.3.0）及 `backend/refunds.py`。

- POST 配置地址：Bearer 认证，`Idempotency-Key` 为原 `space-` 请求键；JSON 仅 `authorized:true` 及一个含 `email/password/totp_secret` 的 accounts 条目。
- 200 返回 `ids:[id]`，必须恰好一个有效编号；只记录受理，不当作办理成功。
- GET 配置地址 + `/id`，每 15 秒查询。读取 `order.id/email/status`，核对编号和邮箱；不接受缺失或不匹配身份的状态。
- queued、processing、verifying、attention 继续查询原单；succeeded 标记商户步骤完成；failed、cancelled、banned 停止自动查询并显示失败。未知状态或查询错误保留原单继续查询。
- 提交响应丢失按已有最多三次规则重试同一请求；幂等键、地址、密钥、密码/2FA 均来自加密快照，不使用后来修改的配置。已有申请不得因换供应商再次创建订单。
- 原商户仍支持原单对象/refund 包装、批次回执及批次查询。历史无 provider 快照明确归原商户。

星桥 quote 的 fee 单位为 cent_R；本地“API 商户每次成功收费（USD）”仍为人工配置的卡台成本，不从星桥 fee 推断美元。最终成功记录一次、费用提交时锁定。商户完成不等于银行卡回款，原回款核对、下游分组收尾及停止规则保持。

供应商写入账号商户进度并展示，审计增加 merchant_provider。密钥、密码和 2FA 不出现在进度或配置回显。拒绝 HTTP 重定向，错误不回显上游原始凭据内容。

## 验证

隔离测试覆盖两供应商密钥隔离、旧客户端与推送设置保存兼容、旧快照、24 并发准备同一申请、切换供应商后原单续跑、提交响应丢失及重启恢复、单一受理编号、身份校验、各状态、费用快照和前端切换/保存。所有上游请求使用测试服务器，无真实代退或付款测试。

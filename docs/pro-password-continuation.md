# Pro 全自动第一步优先密码登录

2026-11-18：用户要求第一次碰到邮箱验证码页先继续密码和 2FA；密码/MFA 后仍需邮箱验证码，再使用 Space 原有取码流程。授权推送并更新两套 Space。

修改限于 ContinuousProLogin。选择密码登录且 identifier 明确返回 passwordless_login 邮箱页时，同一个客户端 GET client_auth_session_dump 核对账号与模式，再提交原 password/verify、按上游要求完成 TOTP。Cookie、代理和客户端保持，不重新授权。每次登录最多提交一次密码；密码后邮箱挑战走原取码/验证，TOTP 后邮箱挑战补接原取码路径，重复挑战有终止边界。显式选择邮箱登录仍使用邮箱；手机、Passkey 等要求不被当作成功。

仅登录完成后才允许原 pro_recharge RPC；凭据错误、取码失败、网络失败不触发付款。原重试与主备、付款核实、已付款恢复、第三步同会话授权、后续业务与所有配置保持。原 upstream.py 与其他独立登录/合并入口不修改，不重跑旧订单。

验证：Python 协议全套139项通过，Pro连续流程17项包含密码优先不取码、密码后和MFA后取码、错误密码/邮箱不一致/无验证码/重复挑战/代理故障不付款、客户端及Cookie连续性、原邮箱模式不变。相关4组Go HTTP全自动/重试/恢复/登录选择测试40.691秒通过。测试均为隔离模拟，无真实开通、退款或取码。正式镜像、备份与最终版本以父目录生产runbook为准。

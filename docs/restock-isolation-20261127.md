# 补货异常隔离

EJH 开卡响应不确定时，旧逻辑同时保留补货在途和全局开卡占用，造成一个账号阻塞其他账号，直到十分钟 watchdog 或人工处理。

现在准备请求返回异常且没有执行中的账号任务时，单独结束该补货任务，显示“已隔离 · 继续补货”。重启恢复和已停止的外部全自动任务也适用。原账号保留任务关联和停止版本，迟到观察不能恢复占位；仍在运行、等待配置重试、已推送或正在换号的任务不会被误停。

下一轮取得新监控快照后，按原缺口、确认次数、并发和预算选其他账号。原开卡、付款及银行卡占用不会伪造成功或失败，不确定金额保留预算。EJH 未确认开卡仅限制同账号、同补货任务；其他账号可使用正常且匹配模板的卡或新开卡。

EJH 开卡索引首次升级从加密操作记录建立，以后随操作事务更新。账号核对只读未确认操作，日开卡预算只读近期记录，准备失败核对按任务索引读取。

本地验证：响应丢失后隔离并换号、原账号重复开卡拦截、16 路同时隔离只成功一次、重启和旧操作归属、迟到写回、配置重试保留、已停止外部任务、5 秒新快照、50,000 条开卡历史查询、补货前端测试/类型检查/构建。真实开卡和付款未用于测试。正式发布前另运行 Linux 隔离环境的相关 race 回归。

已有的无进展十分钟保护和后台限额、熔断配置仍生效。本修改解决单号待核实占位，不绕过后台主动关闭、预算耗尽等限制。

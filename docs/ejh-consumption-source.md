# EJH 消费查询来源说明

已结束但从未推送下游的历史办理账号没有消费查询来源。此前将这些记录与下游消费查询失败一起统计，余额总览一直提示“账号未查询”。

现在查询投影返回独立 `consumption_state=not_pushed`，页面显示“未推送，无消费数据”。此类账号不计入消费缺失数；其付款、费用和回款仍按原记录统计。`consumption_total` 保持空，不伪造已查询的 0，不改财务历史。

识别范围严格限定为：账号仍存在、全自动已 completed 且订单匹配、没有运行流程；推送状态/供应商/时间/步骤/人工步骤/覆盖记录均无记录；Sub2、VM2、SIWC、CPA 绑定和消费来源/查询时间/有效快照均不存在。正在办理、旧订单不匹配、已删除账号或任意推送证据存在时，仍保留原查询缺失提示。

有效历史消费（包括真实查询的 0）优先于此标识。同一邮箱多笔订单合并时，有消费记录优先；任何仍需查询的订单仍计缺失。卡片、账号明细、总览及财务报表使用相同口径。以后恢复推送/查询来源会立即更新展示缓存。

实现只增加现有关联查询中的布尔投影，以及消费来源变化的缓存版本触发器。没有逐账号网络请求、全量读取账号日志、业务数据迁移、重新付款或消费补写。旧数据库通过新增独立触发器更新，原已存在的缓存触发器保持。

验证：Store 测试覆盖完成/进行中、订单匹配、各种推送/消费证据、删除、真实零值、读投影不改原单及旧缓存触发器升级；API 测试覆盖历史消费优先；前端验证去重、混合缺失、费用不变、日周月累计口径、真实组件渲染及增量刷新。

## 中断推送的核实与明细

总览中的“账号未查询”及“账号未推送”现在可点击，按同一消费汇总口径去重展示邮箱、订单、卡尾号、回款状态及核实记录。只读取页面已有快照，不因展开名单刷新全量数据或调用下游。

推送开始后被人工停止，即使后续退款完成，也不能仅凭缺少下游 ID 自动当作未推送。管理员核实原下游（包括删除历史和使用记录）后，可填写依据并选择“确认未推送”；“恢复自动判断”可撤销。接口为 `PUT /api/ejh/cases/{id}/consumption-review`，沿用后台登录与同源保护，提交 `state`（`not_pushed`/`auto`）、`reason`、`confirm=true`、当前 `expected_key` 和 `expected_revision`。

确认仅适用于仍保留的已完成同一流程、没有下游绑定/消费查询证据的账号。真实消费历史（包括真实 0）及原连接的待确认推送会阻止确认。账号锁、事务、版本与上下文校验防止并发和旧页面覆盖。核实保存于原 case 的独立字段并写审计，不删除推送步骤，不补写消费 0，不修改订单、卡状态或回款。将来出现真实消费时优先使用真实金额；新推送上下文会使旧核实失效；已核实账号删除后保留财务说明。

只新增现有 SQL 的轻量投影及缓存失效条件；下游待确认记录与消费历史仅在管理员提交核实时检查，不增加总览逐账号查询。

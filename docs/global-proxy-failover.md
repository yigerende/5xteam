# 全局登录代理主备冷却

## 背景与设置

2026-11-12 正式只读日志：marciamiotti687（15:41）、eskassiam（14:48）的登录请求报 CONNECT tunnel failed, response 504；当时 OAuth 策略为 global，主用“菲律宾”。原实现只变更代理会话，重新登录仍选择同一主用，没有跨任务持久冷却。

接口设置 → 接口与网络：上方全局代理为主用，增加有序备用列表；故障冷却默认300秒（10～3600）、恢复测试默认3次（1～10，留空保存null）、测试间隔默认5秒（1～300）。测试通过一次即恢复；全部测试失败再次冷却。默认不替用户选择其他代理作为备用，原主用和代理地址保持。选择“当前任务最少”时沿用原池内负载策略，但跳过冷却及测试中的代理。

代理管理在名称下显示冷却倒计时、恢复时间及测试状态。页面每10秒只读本地健康快照、浏览器每秒计算剩余时间，隐藏页面不轮询。状态接口不返回代理凭据。

## 登录失败后的动作

Pro手动全自动和自动补货共用连续登录入口。实际登录请求出现明确连接/DNS/隧道/网络超时错误，立即记录当前线路故障并冷却，结束失败客户端，下一轮立即选可用备用从头登录，不等待原业务重试间隔。保留原账号、卡和付款身份，不占账号业务重试次数；原代理连接恢复次数上限保留。

401/403/407/429、验证码、密码/账号异常、证书校验失败、本机池繁忙和取消操作不触发本规则。出口IP观测失败也不单独触发。旧HTTP错误不因包含“网络”二字就被当成代理故障。

没有可用线路时全自动显示等待恢复，最多每30秒重新选择，不消耗登录/账号重试次数，不直连，停止任务立即结束等待。独立OAuth新任务同样避开冷却代理；本次故障上报来自Pro全自动的真实登录阶段。

单个成功会话从登录到后续使用同一个地址，不在运行中切换。进入付款RPC后即关闭本次登录故障换线判定；已提交或结果未知的付款不因此重放。原已付款恢复登录如遇故障，只在原恢复授权路径切换备用重新登录，最多额外3次，不执行付款。

## 恢复与并发

健康状态保存在SQLite独立表global_proxy_health；地址和凭据的哈希区分资源，不存登录异常原文。故障按取得代理时的generation比较后更新；同代多个失败只计一次，晚到旧结果不会延长/清除新冷却。修改代理地址或凭据使用新状态；删除后的旧请求不能重新标记资源。

后台按到期索引每5秒扫描，最多同时2项测试，60秒领取租约，单项20秒上限；网络期间不持数据库锁。恢复测试仅通过代理对auth.openai.com、chatgpt.com发普通HTTPS请求，不提交账号、验证码或业务请求；HTTP鉴权/挑战响应说明传输可达，407及5xx不当作恢复成功。测试间隔从上次完成时计算，调度可能有最多约5秒扫描延迟。

恢复测试期间正常新任务继续走可用备用；测试通过后新登录优先主用。测试失败按配置次数和间隔续测，耗尽重新冷却；留空则冷却截止直接恢复，不发测试请求。重启保留冷却和待测状态，过期测试租约重新领取，旧工作者不能覆盖新结果。

母号专属代理、已经开始的会话、Sub2推送后的代理解绑以及供应商付款请求保持各自原绑定，不通过这一功能换线。

## 验证与发布

隔离测试覆盖20并发失败仅一次冷却、主备顺序、全部不可用等待、重启、恢复间隔和次数、空值跳过、旧测试结果、凭据修改隔离、非网络错误排除和真实全自动调度立即重登且保留付款身份、已付款恢复换线不再付款、全部冷却时停止和重试计数保持。前端真实组件验证默认值/备用选择/空值及倒计时。测试不使用真实账号登录或付款。

发布新增表及代码，保持正式主用、备用未选择、业务配置和主密钥；旧版可忽略新表，回滚应用会暂停冷却调度。恢复新版后继续处理已持久化的任务。

# Pro 降智处理前暂停 Sub2 调度

Pro 管理 → 降智检测新增“达到降智条件后，先暂停该账号的 Sub2 调度”。
接口字段为 `pause_before_action`，随原降智设置保存，默认关闭，旧配置不改变行为。

开启后的顺序：

1. 沿用原检测条件、有效期和连续失败次数。检测失败达限仍先测试连接；测试正常不暂停、不执行降智处理。
2. 对绑定的当前 Sub2 账号读取调度状态；已暂停直接继续，否则关闭调度并再次读取确认。
3. 确认暂停后才执行所选的切换分组、合并/删除/API 商户或推送 SIWC。合并任务排队后，在原有降智结果复核处再次确认调度暂停。

暂停请求和核验合计最多等待 15 秒。暂停失败或缺少明确的调度状态时，本轮不执行后处理；账号降智检测详情显示原因，按原查询间隔继续尝试，不消耗合并业务重试次数。写入响应丢失但读取确认已暂停时可以继续。

网络请求后再次核对配置、账号绑定、停止状态及结果有效期，防止继续处理已经变更的账号。已经开始的后处理沿用原逻辑继续收尾。

开关只控制该账号的暂停，不暂停整个 Sub2 服务。关闭开关不会恢复已暂停账号；“恢复正常后自动恢复原分组”仍仅恢复分组，不恢复调度。需要恢复调度时在 Sub2 操作。

验证采用本地模拟接口，覆盖三种处理分支、暂停失败后的重试、响应丢失、已暂停、无调度字段、无效检测结果、连接复核恢复、网络等待期间改配置、排队期间恢复调度、配置读写和默认关闭。没有向真实账号发起暂停或业务请求。

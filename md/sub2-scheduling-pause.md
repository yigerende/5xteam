# Sub2 暂停调度超时移出

“推送设置 / Sub2”新增“暂停调度超时移出（秒）”，默认 0。

- 0：关闭，不请求暂停调度接口。
- 大于 0：开启额度检测、且账号允许自动移出时，沿用额度检测间隔检查 Sub2 调度开关；连续暂停秒数超过阈值后，按原配置移出空间并删除 Sub2 账号。手动暂停也计入。
- 恢复调度后原暂停时间清除，再次暂停重新计时。暂停秒数由 Sub2 服务器计算，不受 Space 时钟偏差影响。
- 请求失败、接口不支持、账号或邮箱不匹配不触发本项清退；原额度判断继续执行。正式移出前会复核账号、配置和这一次暂停的起始时间。
- 手动额度查询也沿用此规则。CPA 不受影响。删除失败沿用原清理重试，不重复移出空间。

配置字段：`scheduling_pause_timeout_seconds`，非负整数。新旧两个保存设置接口都支持；省略保留旧值，明确填写 0 才关闭。

依赖 Qerkai 的管理员接口：`GET /api/v1/admin/accounts/scheduling-paused?account_ids=42`。沿用现有 Sub2 管理员登录；部署时先更新 Qerkai。升级前已经暂停的账号，由 Qerkai 从升级时开始计时。

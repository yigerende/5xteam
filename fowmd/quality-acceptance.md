# 降智检测验收记录

验收日期：2026-09-18。适用 chatgpt-space-merge、chapt-space-user 及配套 Qerkai-sub2api。

## 六项核对

| 项目 | 实现与验证 |
| --- | --- |
| 多题检测 | 自定义题目/答案、三种判断方式、排序启停；异常换题、正常清零、网络失败重试原题；配置和进度持久化 |
| 模型一致性 | 独立开关，仅当前轮次最近三条指定模型记录；时间顺序处理、ID 去重、忽略旧轮次和迟到旧样本 |
| 轻量接口 | 管理员鉴权，10 账号/批、最多 30 条；单 SQL、无 COUNT/OFFSET/关联加载；管理端批次串行，启动间隔至少 500ms |
| 异常处理 | 独立计数，共用连续异常阈值；母号强制踢出或切换分组；并发不重复处理，缺失/错误不判降智，动作失败重试 |
| 页面 | 八张统计卡固定两行四列，题目/模型/处理三页签；智商列上下显示、独立倒计时、可查看与导出详细日志；手机输入框无横向溢出 |
| 兼容性 | 两个管理项目同步；沿用账号锁、母号锁与操作间隔、异步日志；旧配置保留题目，重启保留去重记录；重登不覆盖降智分组 |

## Qerkai 改动边界

仅新增轻量模型日志读取文件、测试及两条相关路由，并按确认复用现有 `POST /api/v1/admin/accounts/{id}/test`：OAuth/Responses 分支使用传入 prompt，支持可选 reasoning_effort，开始事件确认题目已生效。不新增答题接口。

原有文件仅涉及 `account_handler.go`、`account_test_service.go`、`routes/admin.go`。空提示词和原有无参数调用仍为 hi，保留现有认证、代理、请求头、模型映射、错误处理及测试成功后的状态恢复。普通网关转发、额度、计费、数据库结构未修改。

管理端只调用 Sub2，不直接请求 OpenAI，不发送或覆盖代理。旧 Sub2 未确认自定义题目生效时返回检测失败，避免将连通性回答误判成答错。

## 测试边界

使用临时 SQLite、模拟 Sub2/OpenAI 与 SQL mock，没有使用生产账号或消耗真实账号额度，没有修改正常运行服务的数据。

未进行真实 PostgreSQL 数据量压测、真实 OpenAI 答题或生产部署验证。Windows 当前缺少 race 所需的 CGO 工具链，执行了重复并发场景测试，但不能等同于 `go test -race`。

部署顺序：先更新 Qerkai-sub2api，再更新两个管理端。默认降智总开关关闭。

# Pro 迁移、银行卡限额与定时开通

两个项目使用相同的迁移格式和调度规则。

## JSON 导入导出

Pro 账号列表顶部的“导入 / 导出”支持导出已选账号，或当前筛选条件下的全部账号。文件包含邮箱及 GPT 凭证、AT/RT、Session、套餐、下游关联、全自动六阶段、空间四步进度和 GPTPay 原订单快照。

文件含敏感凭据，包括查询原订单所需的供应商凭据和原付款卡信息。请只在自己的环境之间迁移并妥善保存。目标环境重新加密入库，不需要复制来源数据库密钥。

迁移前停止来源任务。目标环境导入后保留进度并暂停自动调度；默认跳过已有邮箱，可以显式选择覆盖。重复导入同一快照不会回退已经推进的进度。

“继续迁移流程”根据保存进度续跑：已有新 RT/AT 可继续推送和查额度；已开始空间流程可跳过成功步骤继续。正在执行的内存登录会话不能跨服务器迁移，需使用单项登录按钮重新建立；已有付款订单不会自动重新创建。付款或空间合并结果不确定时先查询、核实，再继续。

母号通过真实 Team ID 匹配目标环境账号，沿用目标环境专属代理。下游服务地址及管理员身份一致才使用原账号 ID；不一致时先推送当前下游。全局设置、母号凭据、代理配置不会随账号文件覆盖。

## 银行卡限额

“Pro 全自动配置”中的单卡账号上限默认 3。银行卡列表显示成功开通账号数、在途数和剩余名额；成功与在途按邮箱去重计算。

同一张实体卡重复添加、删除后重建仍共用历史计数。原订单导入后也计入该卡使用量。未确认结果的付款继续占位，确认失败后释放；空间合并不会恢复银行卡开通名额。

手动开通及全自动开通统一使用数据库容量检查。登录前预占银行卡名额，创建订单时转为订单占位，防止并发抢用导致超限。满额、禁用或过期的卡不出现在可选列表。

## 定时全自动 Pro

默认关闭。默认最大未合并数为 5，检查间隔 120 秒。仅从 Pro 管理的新账号中，按进入列表时间优先选择；不会导入全部邮件账号，不会自动重试已付费或曾启动失败的账号。

每批补充数量为：`min(并发账号数, 最大未合并数 - 已开通未合并数 - 开通在途数)`，还受可用银行卡名额限制。已付款尚未推送的账号也计入未合并数，防止登录或推送失败导致额外开通。

同一时间只有一批补充任务。各账号按配置并发运行；本批推送 Sub2 并成功完成首次额度刷新后，才允许启动下一批。首次额度失败时保留本批等待重试，不重复付款。成功查到额度但还未消耗达标时，本批补充结束，账号继续按自身额度间隔等待，达到阈值后执行原空间四步流程。

Pro 执行记录保存每次检查原因、账号、进度和错误，可打开账号完整日志。重启后原运行会话标记中断，已提交订单继续占位，不自动重复付款；额度等待任务沿用已保存凭证继续检查。

“定时查额度”和“查额度达标后自动合并”两个开关用于手动处理的 Pro 账号。全自动任务自身负责定时额度检查及达标合并。

## 批量删除

Pro 账号列表勾选后可点击“批量删除”，确认后删除所选本地账号、凭证及关联的 Team 轮转记录。不会移回邮件管理，不会操作 OpenAI、Sub2 或 CPA；供应商订单、银行卡使用量、日志和空间历史保留。

正在登录、执行全自动、合并或其他账号操作，以及有未结束订单或银行卡占位的账号不能删除。等待额度但没有在执行请求的账号可以删除，删除后不再调度。每个账号独立返回结果，失败账号保留勾选并显示原因；取消确认不会发送删除请求。

## 验证范围

包含独立数据库迁移、重复导入、订单冲突回滚、母号映射、下游地址隔离、迁移后仅执行剩余步骤、单卡并发抢占、最大未合并数、额度失败阻挡新批次、浏览器导入导出进度与卡片显示。付款、登录及下游测试使用隔离服务，不产生真实订单。

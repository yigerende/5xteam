# Team 轮转降智检测

## 部署

本功能同时提供于 chatgpt-space-merge 与 chapt-space-user。先更新配套 Qerkai-sub2api 后端，再更新管理端。答题复用现有单账号测试接口，新增的接口仅用于轻量模型日志查询（沿用管理员认证）：

- `POST /api/v1/admin/accounts/{id}/test`（现有接口）
- `GET /api/v1/admin/usage/model-audit-capabilities`
- `POST /api/v1/admin/usage/model-audit`

开启模型检查时会验证日志接口能力。答题的 test_start 事件确认自定义题目和推理强度已生效；旧 Sub2 缺少确认时只记检测失败，不判降智。CPA 暂不支持，切换到 CPA 后检测暂停。本次没有新增 Python / Docker 系统依赖。Sub2 前方反向代理的读取超时应大于探测超时，默认建议至少 210 秒。

探测请求示例：

```json
{"model_id":"gpt-6-astra","prompt":"自定义题目","reasoning_effort":"xhigh"}
```

答题接口返回现有 SSE 事件 test_start、content、test_complete、error。管理端合并 content，只接受完整成功流，从 test_start 到 test_complete 计算总耗时，使用本地配置限制超时。管理员接口 401 与事件明确报告的上游 401 分开处理。

管理端只调用 Sub2 指定账号测试接口，不直接访问 OpenAI，不传递或覆盖代理配置。Sub2 使用其自身账号代理及现有出站链路完成探测；本项目全局代理和原 OAuth 代理分配均不修改。Sub2 单账号测试仅补充自定义题目和可选推理强度，空题目仍发 hi，原认证、模型映射、错误处理、调度恢复行为保持不变。

## 默认配置

| 设置 | 默认值 |
| --- | --- |
| 总开关 | 关闭，升级不会自动处理账号 |
| 模型 / 推理强度 | gpt-6-astra / xhigh |
| 判断方式 | 内容＋耗时，两项均通过 |
| 内容匹配 | 题库每题独立标准答案 |
| 耗时阈值 | 严格小于 20000 ms |
| 正常检测间隔 | 300 秒 |
| 并发 / 请求超时 | 8 / 180 秒 |
| 每账号检测记录显示上限 | 200 条 |
| 连续异常次数 / 复测间隔 | 2 次 / 60 秒 |
| 确认后的动作 | 母号强制踢出，禁止复用 |
| 自动恢复分组 | 关闭；开启后连续正常 2 次恢复 |
| 模型一致性检测 | 关闭；默认 gpt-6-astra，每 60 秒 |
| 日志请求 | 每批最多10账号，每账号最近3条，串行且启动间隔至少500ms |

默认题库：糖果最坏情况（圆苹果7、圆桃子9、圆西瓜8、星苹果7、星桃子6、星西瓜4，保证圆苹果与星桃子或圆桃子与星苹果至少一组，答案29）；3点15分时钟夹角（7.5）；增加20%再减少20%（96）。升级保留已经保存的旧题目，不覆盖自定义内容。

每次只问一道启用题目。有效异常后按复测间隔换下一题，有效正常回答清零并等待正常间隔；网络错误重试当前题。题库循环、进度持久化，支持启停、排序和每题耗时阈值。

问题和答案均可修改并保存，也支持关键词和 Go 正则。标准答案模式要求单独一行 `FINAL_ANSWER=答案`，也接受只返回标准答案本身；不会把配置的答案发给模型。仅耗时模式不使用内容规则。

耗时为管理端收到测试开始事件至完整回答完成事件的时间，不是首字延迟；包含网络、上游处理和可能的反向代理流缓冲时间。测题结果只是配置规则的结果，不是对账号智力或底层模型的权威判断。启用会消耗真实额度，建议先观察单号检测记录再调整规则。

## 检测与处理

只检测仍在空间内、已成功推送到当前 Sub2、非死号的账号。题目检测通过指定账号 ID 调用现有测试，不走普通对话的账号池调度；保留 Sub2 原有模型映射与 Codex 请求链路。模型检查独立开关，只读取下述轻量接口，不额外请求 OpenAI。

## 轻量模型日志接口

管理员鉴权及标准 Sub2 响应封装不变。请求体示例：

```json
{"model":"gpt-6-astra","accounts":[{"account_id":123,"since":"2026-09-17T12:00:00Z"}]}
```

每批1～10个不同账号，since取当前轮次进入、推送、开启检测时间中的最晚时间。每账号只返回最近3条指定实际发送模型的记录，字段为id、account_id、created_at、requested_model、sent_model、response_model、mismatch；无记录时logs为空。返回data.accounts数组，无总数和翻页。

查询使用现有账号/时间索引，不COUNT、不OFFSET、不关联加载用户或分组。接口数据库请求限时5秒，最多2个同时执行；请求体限制16KB，不支持任意增大返回条数，不改变数据库结构或原日志接口。管理端每轮最多20个批次、30秒检查预算，按最久未检查账号优先轮询；超时退避，下次续查最新样本而非补拉全量历史。

本地按时间从旧到新处理，保存最近日志ID去重及最新样本时间。晚于已处理进度的新样本才计数，旧轮次/重复/延迟旧记录不回退状态。检查的是连续观察到的新样本，不声称覆盖期间的所有请求。正常记录清零，不一致记录加一；缺少模型信息、查询失败不改变连续次数，日期版本后缀差异单独展示不作为跨模型异常。没有新记录保留既有判断。

两种检测共用阈值但独立计数，任一达到阈值只执行一次动作。自动恢复需要所有启用检测都满足连续正常要求，已确认异常的来源被关闭时不自动恢复。切换配置或轮次时丢弃在途旧结果。前端只读取本地状态，答题和模型检查各自显示倒计时；智商情况同一列上下显示两项结果。

- 三种模式：内容＋耗时、仅耗时、仅内容。
- 有效回答未通过规则才增加连续异常次数；一次有效正常回答即清零。
- 401、403、429、网络失败、超时和不完整流都是检测失败，不增加或清零异常次数。明确上游 401 按现有 401 配置处理，不当成降智。
- 默认连续异常 2 次后才执行动作，不是首次异常就踢。
- 母号踢出复用原有专属代理、同母号串行及操作间隔；失败会重试。已踢出但下游清理失败时只重试清理。
- 分组模式保留空间及 Sub2 原账号 ID，移除配置的正常组、加入降智组，其他分组保留。写入前持久化恢复基线，写入后重新读取校验；失败只重试动作。
- 重登更新原账号凭据，不覆盖降智分组。新轮次重新推送已标记降智账号时仍使用降智组。
- 手动恢复分组会加回先前移除的正常组、移除检测所新增的降智组，保留其他当前组；不会复活死号或自动重新进入空间。
- 每批不重叠，同账号与原有授权/监控互斥；正在忙的账号留到后续检测。规则、轮次、下游绑定变化时不应用旧探测结果。
- 已确认并保存的分组处理计划不会因编辑配置而偷偷换成另一个动作；需要改变已处理账号的处置时，先人工恢复再按新配置检测。

记录复用现有异步内存队列和后台批量落库，包含问题、规则、返回内容、耗时、连续次数、分组/踢出结果，不记录令牌。日志仍按既有规则只保留 2 天；200 条仅为账号检测记录窗口的显示上限。

## 顶部统计

设置页顶部显示当前符合条件的账号数、降智/正常/检测失败、已自动处理、内容/耗时达标、已踢出与预计每日探测数，并显示最近一次及下次检测时间（北京时间）。全部使用本地数据库聚合，不会触发探测或读取使用日志。统计每 10 秒随页面状态刷新，编辑中的表单不会被覆盖。

正常、失败、疑似和内容/耗时达标按照当前保存的规则版本统计；改题后旧规则结果不会混入。降智分组、已踢出按现存账号记录统计，不是永久历史累计；手动删除记录后相应统计也会减少。每日探测数是账号数乘以 86400 / 已保存间隔的估算，不含重试、忙账号跳过与手动检测，不是实际计费次数。

## 验证范围

使用本地模拟上游和临时 SQLite，覆盖三种判断方式、自定义题目、成功清零、HTTP/流错误、不重复执行、重启恢复、分组恢复、失败重试、配置变更丢弃旧结果、同账号并发互斥、同母号串行踢出与关闭取消。未使用真实账号测试，也未启用生产检测。
